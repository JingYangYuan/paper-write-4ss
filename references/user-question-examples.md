# 结构化提问规范（`ask_user`）

本规范定义 `paper-master-4ss` 中所有交互式提问、确认与阻断提示的字段格式与执行规则。`ask_user` 为与运行环境无关的通用能力，实际调用按 `references/runtime-adapter.md` §5 的探测结果映射（具备结构化提问工具时调用该工具；仅具备自然语言通道时在单轮回复中列明选项；能力缺失时记录 `ask_user=能力缺失`）。各模块局部业务提问均须遵守本格式约定。

## 一、标准字段结构

```text
question: "面向用户的一句话问题。"
header: "12字以内短标题"
options: [
  {label: "推荐选项", description: "说明选择该项后的执行路径与影响"},
  {label: "备选选项", description: "说明适用条件或代价"}
]
```

编写要求：
- `question` 表述清晰直接，避免堆砌内部协议术语；
- `header` 简短稳定（建议 ≤12 字），用于界面标签或日志摘要；
- `options` 提供 2–4 个互斥选项，每项包含 `label` 与 `description`；
- 推荐选项置于首位，`description` 须说明推荐理由与实际影响，避免仅写「推荐」。

## 二、自由输入型

无法预设枚举值，或须由用户提供具体路径、研究主题、期刊名或数据集名称时，使用空选项列表并由用户自由输入：

```text
question: "请提供你的研究主题、数据路径或目标期刊。"
header: "自由补充"
options: []
```

执行规则：自由输入型不得由模型代填默认答案；用户未提供时标记为 `未确认` 或转入最小可行路径。

## 三、推荐 / 不确定型

当用户可能尚难决策时，保留「按推荐执行」或「不确定，请推荐」选项：

```text
question: "下一步按哪个方向推进？"
header: "方向确认"
options: [
  {label: "按推荐执行", description: "采用当前证据最充分、风险最低的路径"},
  {label: "收窄范围", description: "由用户指定理论、机制、人群、时期或材料边界"},
  {label: "不确定，请推荐", description: "根据已读材料给出主方案与备选方案供参考"}
]
```

执行规则：选择「不确定，请推荐」时，须说明推荐依据，并在过程日志中注明该方向为基于现有材料的推断推荐而非用户主动指定。

## 四、阻断确认型

遇到多席位创建、CNKI 登录/验证码、写文件授权、外部依赖缺失或关键输入缺口时，使用阻断确认型：

```text
question: "当前步骤被阻断，请选择后续处理方式。"
header: "阻断确认"
options: [
  {label: "已处理，继续", description: "已完成验证码、登录、授权或补充了必要材料"},
  {label: "稍后再试", description: "暂停当前步骤，等待条件具备后再继续"},
  {label: "放弃本步骤", description: "记录为用户明确放弃或条件不可达，转入允许的回退路径"}
]
```

执行规则：未获得用户确认前不得跳过或继续执行被阻断的步骤，也不得以猜测替代用户选择。

## 五、长期选择固化规则

以下确认结果一旦稳定，须按 `references/project-rules-writing-layer.md` 写入运行环境已有规则文件的 `paper-master-4ss` 标记块（或 `paper-workspace/_index/project-rules.md`）：
- 模块工作模式、研究取向、发表范式、输出路径等长期偏好；
- 多席位辩论（Team）配置选择；
- 文献检索来源的启用或暂缓策略；
- 用户明确指定的目标期刊、论文类型、学历层次与字数要求。

单次临时指令、隐私材料细节与一次性验证码状态不得写入项目规则。

## 六、学术机制图风格确认（`mechanigraph`）

生成纯矢量 SVG 学术机制图前，须通过 `ask_user` 一次性向用户确认以下三项制图风格偏好（能力缺失时在单轮自然语言回复中一并列出并给出建议默认值）：

### 问题 1：拓扑构型流派

```text
question: "请选择学术机制图的拓扑构型流派："
header: "构型流派"
options: [
  {label: "自动匹配", description: "由拓扑顾问依据理论因果关系从 8 类经典学术拓扑中自动匹配最优构型"},
  {label: "流水线时序模型", description: "适用于由前提到产出的多阶段传导链条（可含反馈回路）"},
  {label: "纵向层级架构", description: "适用于宏观制度—中观组织—微观行动的纵向分析框架"},
  {label: "双系统对偶模型", description: "适用于政府与市场、正式与非正式等左右对偶互动治理系统"}
]
```

### 问题 2：外围大边框样式

```text
question: "请选择画面的外围大边框样式："
header: "外边框样式"
options: [
  {label: "实线大外框", description: "期刊出版标准风格，以细实线界定机制分析系统的理论边界"},
  {label: "虚线大外框", description: "强调系统与外部宏观制度或社会环境的开放式交互"},
  {label: "无外围边框", description: "极简风格，主体元素居中展开，四周不设外框"}
]
```

### 问题 3：分箱与连线风格

```text
question: "请选择实体分箱与传导连线的风格偏好："
header: "连线与分箱"
options: [
  {label: "实线为主", description: "实体分箱与传导路径均采用实线，视觉风格统一明确"},
  {label: "虚实结合", description: "核心实体与主因果线用实线，环境分箱、调节变量与反馈线用虚线"}
]
```

执行规则：若用户在原始指令中已明确指定上述任一项（如「用实线大边框」「按双系统绘制」），则跳过对应提问，直接采纳并在产出元数据中记录。
