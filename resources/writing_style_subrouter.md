# 写作风格子路由：学理化梯度、开头范式与结尾范式

本文档是 `write module` 的第三层路由，在方法协议判断（第一层）和发表范式判断（第二层）之后生效。它负责判断三件事：全文学理化梯度、开头从何种小处入手、结尾采用何种收束范式。

---

## 一、使用原则

1. 风格子路由在双层研究路由（research_router.md）完成后生效。
2. 对已有文本进行润色时，应先确认目标梯度，再逐章改写。
3. 梯度不是非此即彼的选择。一篇论文内部，不同章节可以落在不同刻度上。
4. 轻档绝不等于口语化。轻度写法要求从具体处落笔，用精准但不堆砌术语的语言推进。
5. 开头策略负责建立问题入口，结尾范式负责决定全文如何回扣、延展和升维。
6. 本文件只提供路由规则和策略判断，不存放完整范文。具体范文由 `examples/` 与 `example_extractor.py` 管理。

---

## 二、规则一：学理化三梯度

| 梯度 | 核心特征 | 起笔策略 | 平均句长 | 术语处理 |
|------|---------|---------|----------|---------|
| **轻** | 从具体处落笔，让判断从事例、场景或材料中自然浮现 | 具体的人、动作、场景、困境、悖论、数字 | 25-40 字 | 核心术语在叙事推进中自然嵌入，不堆砌定义 |
| **中** | 经验描述与理论概念各半，判断句直接陈述 | 学术判断句或经验现象概括 | 35-50 字 | 术语与经验交替出现 |
| **重** | 概念链推进，抽象名词做主语，以理论语言建构命题 | 理论命题或方法论论断 | 45-65 字 | 高密度理论词汇，概念之间形成推演关系 |

### 轻档铁则

轻档最容易滑向口语化。以下四条是检查标准：

1. **不假装亲切。** 不用"我们来看看""大家都知道""你可能会问"等招呼语。
2. **不降智。** 不把学术判断简化成"其实很简单"式的表述。精准度不打折。
3. **让对象自己说话。** 与其说"这个问题很重要"，不如展示问题是怎么出现的。叙述推进，判断后置。
4. **术语保留但不堆叠。** 关键概念照常出现，但不在一句话内塞入三个以上。

## 三、规则二：从小处入手策略库

引言和文献综述的起笔方式，决定了整篇论文的入口温度。以下十五种策略用于把抽象研究问题压缩到一个可感知、可判断、可继续展开的入口。

### 策略 A：从悖论入手

- **功能**：展现一对反常现象，即事情本应如此，实际却并非如此。
- **结构**：预期 → 现实 → 落差 → 问题浮现
- **适合**：引言首段，需要快速建立问题意识；研究对象存在直观反差。
- **风险提醒**：不要把悖论写成夸张修辞。落差必须由材料、制度、文献或经验事实支撑。

### 策略 B：从制度后果入手

- **功能**：展现某个制度安排、规范要求或制度漏洞如何系统性制造问题。
- **结构**：制度/规则 → 覆盖范围 → 未覆盖部分 → 后果 → 问题浮现
- **适合**：与政策、期刊规范、组织制度、治理规则、复现性审查等话题相关。
- **风险提醒**：不要只批评制度。必须说明制度如何具体作用于研究对象。

### 策略 C：从代际/人际断裂入手

- **功能**：展现知识、经验或判断如何在人员流动和协作传递中丢失。
- **结构**：人员流动或协作场景 → 知识传递机制 → 丢失环节 → 问题浮现
- **适合**：讨论知识传递、训练体系、专业化实践、组织记忆、基础设施缺陷。
- **风险提醒**：不要把断裂写成个人失误。重点应放在传递机制和记录机制。

### 策略 D：从统计数字入手

- **功能**：用一组简洁对比数据建立问题的经验基础。
- **结构**：对比数字 → 结构性差异 → 异常或趋势 → 问题浮现
- **适合**：已有描述统计、元分析、文献计量、横向对比或历时数据。
- **风险提醒**：数字必须服务问题，不要把开头写成结果汇报或数据罗列。

### 策略 E：从训练/学习场景入手

- **功能**：展现一个人进入某项实践时的真实遭遇，以此揭示系统性问题。
- **结构**：新手进入实践 → 学习步骤 → 暴露的制度性缺陷 → 问题浮现
- **适合**：文献综述中引入理论工具，或在引言中讨论训练体系、方法习得、专业社会化。
- **风险提醒**：训练场景只是入口，不能停留在经验随笔。后文必须收束到研究问题。

### 策略 F：从个案异常入手

- **功能**：从一个不符合常规解释的个案细节切入，逼出本文的问题意识。
- **结构**：个案细节 → 常规解释 → 解释失效 → 新问题浮现
- **适合**：案例研究、质性研究、过程追踪、异常案例或反例驱动研究。
- **风险提醒**：异常个案要有代表性或理论价值，不能只是猎奇细节。

### 策略 G：从概念误用入手

- **功能**：指出一个常用概念在既有研究或实践中被过度泛化、混用或误用。
- **结构**：常用概念 → 使用扩散 → 含义混乱 → 重新界定必要性
- **适合**：理论辨析、概念史、规范研究、理论框架建构。
- **风险提醒**：不要以定义堆砌开头。概念问题要连接经验后果或解释失败。

### 策略 H：从历史转折入手

- **功能**：通过一个时间节点或历史变化说明旧问题如何变成新问题。
- **结构**：过去状态 → 关键变化 → 新条件 → 新问题浮现
- **适合**：制度变迁、技术扩散、政策改革、社会结构变化、代际比较。
- **风险提醒**：避免宏大历史铺陈。开头只保留与本文问题直接相关的转折。

### 策略 I：从分类边界入手

- **功能**：指出既有分类、类型或二分法无法安放研究对象。
- **结构**：既有分类 → 边界模糊/遗漏 → 对象无法归类 → 本文切入点
- **适合**：类型学研究、边缘群体研究、组织类型研究、政策对象识别。
- **风险提醒**：不要把分类争议写成术语游戏。要说明分类失灵带来的解释或治理后果。

### 策略 J：从日常实践入手

- **功能**：从普通行动和日常流程中提炼被忽视的机制。
- **结构**：日常行动 → 重复实践 → 隐含规则/机制 → 学术问题
- **适合**：田野研究、组织研究、平台劳动、家庭实践、社区治理。
- **风险提醒**：日常细节要能承载机制分析，不能只是生活化描写。

### 策略 K：从技术中介入手

- **功能**：展现工具、平台、算法或基础设施介入后如何改变行动方式。
- **结构**：技术工具 → 行动方式改变 → 关系/权力/判断改变 → 理论后果
- **适合**：数字社会、平台治理、AI Agent、算法管理、数据基础设施研究。
- **风险提醒**：不要把技术写成外在背景。重点是技术如何中介行动和关系。

### 策略 L：从政策执行缝隙入手

- **功能**：呈现政策目标与执行现场之间的落差。
- **结构**：政策目标 → 执行场景 → 偏差/变形 → 后果 → 问题浮现
- **适合**：公共政策、基层治理、组织执行、街头官僚、制度落实研究。
- **风险提醒**：不要只写"上有政策下有对策"。要识别具体执行机制。

### 策略 M：从组织流程入手

- **功能**：从组织内部的常规流程、审批链条或协作摩擦中发现问题。
- **结构**：组织常规 → 流程节点 → 摩擦/堵点 → 制度性问题
- **适合**：组织社会学、公共管理、企业案例、协作治理、知识管理。
- **风险提醒**：流程描述要服务分析，不要变成操作手册。

### 策略 N：从文献沉默入手

- **功能**：在研究很多的领域中指出一个共同被忽视的对象、过程或判断。
- **结构**：已有研究密集区 → 共同关注点 → 共同忽略点 → 本文缺口
- **适合**：文献综述开头、理论框架前置、研究缺口需要精确定位时。
- **风险提醒**：不能只说"研究较少"。必须说明少在何处、为何重要。

### 策略 O：从评价困境入手

- **功能**：指出既有评价标准无法解释、衡量或比较研究对象。
- **结构**：既有评价标准 → 遇到新对象 → 判断失效 → 新框架需求
- **适合**：政策评估、方法论论文、工具评价、治理绩效、规范判断研究。
- **风险提醒**：不要停留在"标准不够好"。要说明失效发生在哪个判断环节。

### 策略可以组合

同一篇论文的引言可以在不同段落使用不同策略。常见组合包括：

- **D + A**：先用数字给出结构性图景，再用悖论收束为研究问题。
- **F + N**：先呈现异常个案，再指出文献为何没有解释它。
- **B + L**：先交代制度安排，再进入执行缝隙。
- **J + K**：先写日常实践，再说明技术如何改变实践。
- **G + I + O**：先指出概念误用，再展示分类边界和评价困境。

| 问诊线索 | 优先策略 | 备选策略 |

## 四、规则三：结尾范式选择

结尾不是简单收尾，而是决定全文发现如何被重新放回知识脉络、经验世界和未来问题中。结尾可以采用一种主范式，也可以用一主一辅组合。

| 结尾范式 | 核心功能 | 结构 | 适合场景 | 风险提醒 |
|---------|---------|------|----------|----------|
| **总结收束型** | 系统回顾研究对象、方法和主要发现 | 研究对象 → 方法/材料 → 分层发现 → 一句话意义 | 所有论文的结论起始段 | 避免机械重复摘要，应比摘要更有层次 |
| **发现回扣型** | 回到开头提出的问题，说明本文发现如何回应它 | 开头问题 → 关键发现 → 回答方式 → 剩余问题 | 引言问题意识清晰的论文 | 不要只说"回应了问题"，要点明回应路径 |
| **纵横延展型** | 将个案或发现扩展到时间、空间或相邻领域 | 本文发现 → 时间延展/空间比较 → 边界条件 | 案例研究、质性研究、公共管理研究 | 延展必须有边界，不可泛化过度 |
| **限制转展望型** | 把研究限制转化为下一步研究可能 | 具体限制 → 限制原因 → 后续问题 → 未来研究方向 | 需要交代样本、方法、材料局限时 | 全文最后一段不得停在限制本身 |
| **理论升维型** | 将经验发现放回更高层次的理论对话 | 经验发现 → 概念修正 → 理论命题 → 知识贡献 | 理论对话较强、概念建构明显的论文 | 不要突然升维，必须承接前文理论框架 |
| **开放设想型** | 以新的问题、想象空间或研究议程结束全文 | 本文未尽处 → 新问题 → 研究议程 → 开放收束 | 讨论新现象、新技术、新制度转型 | 设想要来自本文发现，不可另起话题 |
| **实践回响型** | 说明研究发现对制度、组织或实践的启示 | 发现 → 实践困境 → 调整方向 → 可审慎推广的启示 | 政策、治理、组织、管理世界风格论文 | 不要写成政策建议清单，应保持学术表达 |

### 结尾范式组合

- **总结收束型 + 发现回扣型**：最稳妥的通用组合，适合多数经验研究。
- **发现回扣型 + 理论升维型**：适合理论贡献较强的论文。
- **总结收束型 + 纵横延展型**：适合案例研究和质性研究。
- **限制转展望型 + 开放设想型**：适合最后一段，尤其是需要避免以研究限制结尾时。
- **实践回响型 + 理论升维型**：适合管理世界风格或公共管理风格，但要避免建议化。

## 五、规则四：各章节学理化边界

不是所有章节都应该落在同一个梯度。以下是根据中文社会科学论文阅读体验确定的默认边界。

| 章节 | 推荐梯度 | 理由 |
|------|---------|------|
| **标题** | 轻-中 | 核心概念可以出现，但不宜堆砌 |
| **摘要** | 中 | 需覆盖全文要素，不可避免地出现术语，但句长应受控 |
| **引言首段** | 轻 | 从小处入手，建立可感知的问题意识 |
| **引言中后段** | 轻→中 | 从具体困境逐步收束为研究问题 |
| **文献综述：脉络梳理** | 中 | 引用密集，但叙述应以"谁说了什么、为什么重要"推进 |
| **文献综述：理论框架引入** | 轻→中 | 理论工具应被经验场景托举，避免直接空降 |
| **文献综述：分析框架建构** | 中→重 | 在此处可以适当升维，建立本文的概念工具 |
| **研究方法与数据** | 轻-中 | 叙事性呈现，让方法选择有理由可见 |
| **经验分析 / 案例演示** | 轻-中 | 让材料自己说话，判断从事例中浮现 |
| **理论对话** | 中→重 | 回到文献脉络，概念链推演 |
| **结论：发现总结** | 轻 | 从具体发现收束，避免术语轰炸 |
| **结论：延展与升维** | 中→重 | 将发现放回更广阔的理论脉络 |

### 核心原则

整篇论文的学理化程度应该呈现一个**浅 U 形曲线**：

```text
引言首段（轻）→ 文献综述（中）→ 分析框架（中→重）
    → 经验分析（轻→中）→ 理论对话（中→重）
    → 结论发现总结（轻）→ 结论升维（中→重）
```

这意味着一篇论文在四个节点需要"降温"：引言起笔、经验分析的主体部分、结论的发现回顾、限制与展望之间的过渡。降温不是降低质量，而是让判断从材料中浮现，让读者先感受到问题的存在再进入理论框架。

## 六、风格子路由提问

Skill 在完成双层研究路由后，如果进入润色、改写或开头/结尾设计模式，应使用 ask_user 增加以下问题。若用户选择"不确定，请推荐"，则根据其余答案自动推荐主策略和备选策略。

结构化示例模块统一遵守 `references/ask-user-question-examples.md`。风格子路由可按以下示例分组提问：

```text
question: "这篇论文最适合从哪类小处进入？"
header: "开头入口"
options: [
  {label: "反常落差", description: "导向 A 悖论或 F 个案异常，用落差快速建立问题意识"},
  {label: "制度执行", description: "导向 B 制度后果、L 政策执行缝隙或 M 组织流程"},
  {label: "概念文献", description: "导向 G 概念误用、I 分类边界、N 文献沉默或 O 评价困境"},
  {label: "不确定，请推荐", description: "由 Skill 根据材料入口、问题性质和读者效果自动推荐"}
]
```

```text
question: "你希望结尾更偏向哪种收束方式？"
header: "结尾范式"
options: [
  {label: "发现回扣", description: "回到开头问题，说明本文如何回答"},
  {label: "理论升维", description: "把经验发现提升为概念、机制或理论命题"},
  {label: "限制转展望", description: "承认边界，并将限制转化为未来研究问题"},
  {label: "不确定，请推荐", description: "由 Skill 根据论文类型和贡献重心推荐结尾主范式"}
]
```

### 问 A：目标学理化程度（整体梯度）

你的论文整体倾向于哪种风格？

- 轻度：从具体处落笔，让问题意识从现象中浮现，术语精简
- 中度：术语与经验各半，直接陈述判断
- 重度：概念链推进，理论语言主导全篇
- 混合：不同章节采用不同梯度（推荐，需进一步确认边界）

### 问 B：问题入口（导向开头主策略）

- 反常现象或解释落差 → A 悖论 / F 个案异常

## 八、轻档写法检查卡

轻档写法不是把论文写浅，而是把抽象判断放回可感知的材料入口。检查时遵守以下标准：

1. **入口具体**：首段应出现可感知的场景、动作、数字、制度环节、文献沉默或判断过程。
2. **判断后置**：不要先抛出宏大判断，再寻找材料证明；应让材料推动判断浮现。
3. **术语节制**：关键术语可以出现，但首段不宜连续堆叠多个抽象概念。
4. **问题可转写**：读者读完首段后，应能用一句话复述本文要解释的落差、困境或缺口。
5. **不写完整故事**：开头只打开问题，不替正文完成分析。
6. **不滑入口语**：避免招呼语、感叹句、过度比喻和教学式说明。
7. **可与结尾呼应**：开头提出的落差、场景、概念困境或评价困境，应在结尾被回扣或升维。
